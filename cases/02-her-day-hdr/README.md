# 案例 02 ·《她的一天》五部 HDR 故事线短片

> **源素材**：本人自拍自有家庭影像，972 条手机素材（其中 256 条原生 HLG），4K 原片不随仓库分发。
> **成片**：5 条不同故事线、张艺谋风格、84–99s、2160×3840、HEVC 10-bit HLG、30fps、带 AAC 音轨。
> **验收**：114 个去重镜头、与第一版 SDR 零素材重复；全片 decode 错误 0；峰值 −2.7~−4.2dB 无削波。
> **工具**：HDR 流水线见 [`../../tools/hdr/`](../../tools/hdr/README.md)；故事线数据见 [`../../tools/hdr/storylines.py`](../../tools/hdr/storylines.py)。

---

## 一、项目背景

第一版《她的一天》是一条 SDR 叙事片（见 [`build_sdr_day.py`](../../tools/hdr/build_sdr_day.py)）。
随后要求：**场景仍围绕“她的一天”，但要真 HDR、要 5 条不同故事线，且与第一版素材不重复**。

由此从“单条 SDR 片”升级到“批量 HDR 竖屏叙事”，沉淀出 [`tools/hdr/`](../../tools/hdr/README.md)
这套三步流水线。案例 01 解决“单条片怎么剪得顺”，本案例解决“**多条 HDR 竖屏片怎么批量、稳定、不重样地产出**”。

| # | 片名 | 主题 | 章节 | 时长 | 镜头 |
|---|---|---|---|---|---|

## 三、选材与剔除（逐帧人工复核）

先 [`scan_manifest.py`](../../tools/hdr/scan_manifest.py) 盘点，再
[`contact_sheets.py`](../../tools/hdr/contact_sheets.py) 抽帧（全库 overview + 入选 4 帧 deep）。
光靠单帧缩略图会漏判方向（无旋转标签），也无法识别“后期二剪”素材，因此按下面清单剔除：

| 剔除类型 | RID | 原因 |
|---|---|---|
| 画中脸 | R142 / R186 / R195 | 成片模板里嵌了另一张人脸（社交软件二剪） |
| 文字模板 | R234 / R259 / R251 | 含平台/贴纸文字，不适合叙事 |
| 屏幕录制 | R255 | 手机录屏，不是实拍 |
| 成人主体 | R083 | 主体不是孩子，偏离“她的一天” |
| 方向异常 | R078 / R085 | 旋转标签与实际朝向冲突，难统一 |
| 低分辨率 | R156（仅保留 2.8s） | 唯一 1080p 源（雕像空镜），按 0.09 取点仅用 2.8s |

另外 972 条里真 HLG 只有 256 条，大量 SDR 旅行批整体不纳入；过短片段（<2s）先在盘点阶段标记。

## 四、方向三模式（核心技术点）

| 模式 | 判据 | 处理 |
|---|---|---|
| `auto` | 旋转标签 `rotation!=0` | 让 ffmpeg 自动旋转并烘焙像素、清标签，只 scale |
| `crop` | `rotation=0` 且编码宽>高（真横屏） | `-noautorotate` + 中心 9:16 裁切 |
| `port` | `rotation=0` 且编码高>=宽（真竖屏） | 不旋转，直接 cover 缩放 |

关键：判据必须读 `rotation` + **编码**宽高，而不是抽一帧 JPG（单帧不带旋转标签）。
混合片段（含横竖段落）在 SDR 基线里用 `hold` 模式单独处理，HDR 版仅保留 auto/crop/port 三种。

## 五、HDR 与时间线

1. **真 HLG**：原生段 `hevc_nvenc main10` + `p010le`，色彩标签
   `bt2020 / arib-std-b67 / bt2020nc / tv`。
2. **SDR 标题卡**：PIL 黑底白字 → 显式 `rgb24` → `zscale` 单步写全 in/out 参数转 HLG。
3. **静音音轨**：标题卡用 `anullsrc` 补 AAC，避免 concat 丢音频。
4. **concat 重编码**：不能 `-c copy`（接缝 non-monotonic DTS）；最终同参数重编码 +
   `-r 30 -vsync cfr` 保证连续时间线。
5. **音量**：统一线性 `volume=0.72`（约 −2.8dB），用线性系数而非负数 dB。
6. **编码**：软编 libx265 约 0.45fps 不可行；NVENC 快约 44 倍，参数
   `-preset p5 -tune hq -rc vbr -cq 21 -b:v 0`。

完整说明见 [`tools/hdr/README.md`](../../tools/hdr/README.md)。

## 六、逐片验收结果（成片实测）

|---|---|---|---|---|---|---|

| 03 追风 | 84.0s | 173MB | 22 | 0 | −3.5dB | 4K/30/HLG ✓ |
| 04 牵着你的手 | 98.7s | 208MB | 25 | 0 | −2.7dB | 4K/30/HLG ✓ |

- 音量峰值 −2.7~−4.2dB，无削波、无静音段。

## 七、墨菲定律 / 对抗性审查（主动披露未覆盖项）

**验证过的**：

| 项目 | 结果 | 验证方式 |
|---|---|---|
| 方向 | auto/crop/port 三模式输出全部竖屏正向 | 逐段 + 全片抽帧人工复核 |
| 色彩 | 5 条均为 HLG、10-bit、bt2020 | ffprobe 回读 `color_transfer/pix_fmt` |
| 时间线 | 全片解码 0 错误，无 non-monotonic DTS | `ffmpeg -v error` 全片扫描 |
| 音量 | 无削波、无静音 | 音量峰值/底噪检测 |
| 去重 | 114 个去重 RID，与 SDR 零重叠 | `storylines.py` 自检 |
| 规格 | 分辨率/帧率/编码/音频一致 | 逐条 ffprobe |

**尚未做、因此不写成“通过”的项**：

1. 没有在真机 HDR 手机上逐部播放、也没有做抖音上传后的**平台显示**验证——本结论仅覆盖本地 ffprobe / 解码 / 抽帧；不同平台可能对 HLG 做二次 tonemap。
2. 仅 R156 一段是 1080p 源放大（2.8s），在 4K 显示器上理论上会软，未做主观观看打分。
3. 抽帧是静态复核，**运动中**的方向/构图没有逐镜动态检查（原始素材方向问题主要出在静态标签）。
4. 调色只做了统一的 HLG 色彩与音量，未做逐镜头曝光/白平衡匹配，跨镜头色调一致性依赖源素材本身。

**保底方案**：

- 若某平台不支持 HLG 直传，可用同素材跑 SDR 基线（`build_sdr_day.py`）或在导出端加 BT.2390 tonemap，不影响选镜与叙事。
- concat 重编码是确定性流程，若出现偶发 DTS 问题，删掉 `hdr_build/<key>/` 重跑该条即可，已做成逐段幂等（段文件存在即跳过）。

## 八、复现步骤

```bash
set HDR_LIBRARY=D:\my_library
python ../../tools/hdr/scan_manifest.py
python ../../tools/hdr/contact_sheets.py overview
python ../../tools/hdr/contact_sheets.py deep
# 确认 ../../tools/hdr/storylines.py 中的 rid/时长/取点
python ../../tools/hdr/build_hlg_films.py
# 逐条 ffprobe 回读 + ffmpeg -v error 全片解码扫描 + 抽帧复核
```

4K 成片单片 170–220MB，不随仓库分发；本案例提供的是可复现的脚本、故事线数据与实测结论。
